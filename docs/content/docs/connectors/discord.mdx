## Quickstart

<Steps>

<Step title="Create a Discord application">

In the <a href="https://discord.com/developers/applications" target="_blank" rel="noopener noreferrer">Discord Developer Portal</a>, create an application. Copy its application ID and public key, and create a bot token.

</Step>

<Step title="Register the command">

Register an `/ask` command with a `prompt` option:

```sh
curl -X PUT "https://discord.com/api/v10/applications/$DISCORD_APPLICATION_ID/commands" \
  -H "Authorization: Bot $DISCORD_BOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '[{"name":"ask","description":"Ask the agent","options":[{"type":3,"name":"prompt","description":"What to ask","required":true}]}]'
```

Install the application to your server with the `applications.commands` scope.

</Step>

<Step title="Add the route">

```sh
npm add @rivet-dev/pi rivetkit hono discord-interactions
```

Run the server with any runtime that serves a fetch handler, for example `npx srvx --import tsx server.ts`. See [HTTP Server](/actors/docs/http-server).

</Step>

<Step title="Set the environment">

```sh
DISCORD_PUBLIC_KEY=...
ANTHROPIC_API_KEY=sk-ant-...
```

</Step>

<Step title="Set the interactions endpoint">

Under **General Information**, set the interactions endpoint URL to `https://<your-worker>/discord/interactions`. Discord sends a ping, which the route answers. Run `/ask` in a channel.

</Step>

</Steps>

## How it works

- The route verifies Discord's Ed25519 signature against the raw body with the application's public key.
- Each Discord channel gets its own agent. Every `/ask` in the channel continues the same conversation.
- Discord expects a response within three seconds and an agent run takes longer, so the route hands the command to the agent's `receive` action and defers the reply. The `receive` action schedules `reply`, which prompts the agent and edits the deferred message. Interaction tokens stay valid for 15 minutes, and a message holds up to 2,000 characters. The schedule is saved with the agent, so the reply still runs if the request that delivered the message goes away.
- A message that arrives while the agent is answering waits as a follow-up, and gets its own reply when its run ends.
- The prompt's `requestId` is the interaction's id, so a command delivered twice runs the agent only once.

## Configure

| Variable | Purpose |
| --- | --- |
| `DISCORD_PUBLIC_KEY` | **Required.** Verifies that requests come from Discord. |
| `DISCORD_APPLICATION_ID` | Registers the command. Not needed by the server. |
| `DISCORD_BOT_TOKEN` | Registers the command. Not needed by the server. |
| `ANTHROPIC_API_KEY` | **Required.** The agent's model key. For another provider, change `model` and set its key instead, such as `OPENAI_API_KEY` or `OPENROUTER_API_KEY`. See [LLM API Keys](/agents/docs/api-keys). |

## Supported events

| Discord interaction | Webhook path | What the route does |
| --- | --- | --- |
| `PING` | `/discord/interactions` | Answers Discord's endpoint check. |
| <a href="https://discord.com/developers/docs/interactions/application-commands" target="_blank" rel="noopener noreferrer">Application command</a> `/ask` | `/discord/interactions` | Hands the command to the channel's agent and defers. The agent edits the reply. |
