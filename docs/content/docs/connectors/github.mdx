## Quickstart

<Steps>

<Step title="Create a bot account and token">

Create a GitHub account for the agent, or use your own, and a <a href="https://github.com/settings/personal-access-tokens" target="_blank" rel="noopener noreferrer">fine-grained personal access token</a> for the repository with the **Issues** permission set to read and write. It covers comments on pull requests too.

</Step>

<Step title="Add the route">

```sh
npm add @rivet-dev/pi rivetkit hono @octokit/rest @octokit/webhooks-methods
```

<CodeGroup workspace>
<CodeSnippet file="examples/docs/connectors/github/server.ts" title="server.ts" />
<CodeSnippet file="examples/docs/connectors/github/github.ts" title="github.ts" />
</CodeGroup>

Run the server with any runtime that serves a fetch handler, for example `npx srvx --import tsx server.ts`. See [HTTP Server](/actors/docs/http-server).

</Step>

<Step title="Set the environment">

```sh
GITHUB_WEBHOOK_SECRET=...
GITHUB_TOKEN=github_pat_...
GITHUB_BOT_LOGIN=my-agent
ANTHROPIC_API_KEY=sk-ant-...
```

</Step>

<Step title="Add the webhook">

In the repository's **Settings > Webhooks**, add a webhook with the payload URL `https://<your-worker>/github/webhook`, content type `application/json`, your secret, and the **Issue comments** event. Comment `@my-agent` on an issue or pull request.

</Step>

</Steps>

## How it works

- The route verifies GitHub's `X-Hub-Signature-256` signature against the raw body.
- Each issue or pull request gets its own agent, keyed by owner, repository, and number. Every mention in the thread continues the same conversation.
- The route only answers new comments that mention the bot, and never the bot's own comments, so replies do not loop.
- GitHub times out a delivery after ten seconds, so the route only hands the comment to the agent's `receive` action and returns. The `receive` action schedules `reply`, which prompts the agent and posts the answer as a comment with Octokit. The schedule is saved with the agent, so the reply still runs if the request that delivered the message goes away.
- A message that arrives while the agent is answering waits as a follow-up, and gets its own reply when its run ends.
- The prompt's `requestId` is the comment's id, so a redelivered webhook runs the agent only once.

## Configure

| Variable | Purpose |
| --- | --- |
| `GITHUB_WEBHOOK_SECRET` | **Required.** Verifies that deliveries come from GitHub. |
| `GITHUB_TOKEN` | **Required.** Posts replies as the bot account. |
| `GITHUB_BOT_LOGIN` | **Required.** The bot's username. Comments that mention it start a reply. |
| `ANTHROPIC_API_KEY` | **Required.** The agent's model key. For another provider, change `model` and set its key instead, such as `OPENAI_API_KEY` or `OPENROUTER_API_KEY`. See [LLM API Keys](/agents/docs/api-keys). |
