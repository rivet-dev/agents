An agent doesn't need a sandbox. Without one, its file tools work on files in the Actor's own database. Add a sandbox only when the agent needs a shell.

| | Files | Shell | Setup |
| --- | --- | --- | --- |
| **No sandbox** | In the Actor's SQLite database | None. `bash` returns an error. | None |
| **Sandbox** | In the sandbox | `bash` runs in the sandbox | agentOS, or a provider account |

## Without a sandbox

Leave out the `sandbox` option. Pi's `read`, `write`, and `edit` tools then work on files stored in the Actor's own SQLite database:

<CodeSnippet file="examples/docs/sandboxes/no-sandbox.ts" title="server.ts" />

- **Nothing to provision.** There is no sandbox to create, pay for, pause, or delete.
- **Files are durable.** They are saved with the conversation and survive sleep, crashes, and upgrades.
- **No shell.** `bash` returns an error, so this agent installs only the file tools.

See [Built-in Tools](/agents/docs/built-in-tools) for what each tool does.

## With a sandbox

When the agent needs to run commands, such as tests or a build, pass a sandbox provider. <a href="https://github.com/rivet-dev/agents/tree/main/packages/sandbox-adapter" target="_blank" rel="noopener noreferrer">`@rivet-dev/sandbox-adapter`</a> gives each Actor its own sandbox, and `CodingTools` run there.

## Providers

| Provider | SDK | While the Actor sleeps | When the Actor is destroyed |
| --- | --- | --- | --- |
| [agentOS](/agentos/docs) | None | Sleeps when idle, and keeps its files | Left in place |
| <a href="https://e2b.dev" target="_blank" rel="noopener noreferrer">E2B</a> | `e2b` | Paused | Deleted |
| <a href="https://daytona.io" target="_blank" rel="noopener noreferrer">Daytona</a> | `@daytonaio/sdk` | Stopped | Deleted |
| <a href="https://freestyle.sh" target="_blank" rel="noopener noreferrer">Freestyle</a> | `freestyle` | Paused | Deleted |
| <a href="https://docs.docker.com" target="_blank" rel="noopener noreferrer">Docker</a> | None. Uses the `docker` CLI. | Stopped | Removed |

Provider credentials stay on your worker and never enter the sandbox.

### agentOS

```sh
npm add @rivet-dev/sandbox-adapter
```

<CodeSnippet file="examples/docs/sandboxes/agentos.ts" title="server.ts" />

| Option | Description |
| --- | --- |
| `cwd` | Working directory inside the VM. Defaults to `/workspace`. |
| `software` | Packages installed when the VM is created, such as coreutils for `sh`. |

The VM is an agentOS Actor in the `services` pool, with the key `["sandbox", <agent Actor id>]`. It keeps its files in its own SQLite database, so they persist while the agent sleeps. The VM sleeps on its own when idle. Destroying the agent leaves the VM and its files in place.

### E2B

```sh
npm add @rivet-dev/sandbox-adapter e2b
```

<CodeSnippet file="examples/docs/sandboxes/e2b.ts" title="server.ts" />

| Option | Description |
| --- | --- |
| `template` | Template name or id. Defaults to `base`. |
| `create` | Options for E2B's `Sandbox.create`. The API key defaults to `E2B_API_KEY`. |
| `cwd` | Working directory inside the sandbox. Defaults to `/home/user`. |

E2B ends a sandbox when its timeout runs out, so the provider creates sandboxes that pause on timeout and resume on the next call.

### Daytona

```sh
npm add @rivet-dev/sandbox-adapter @daytonaio/sdk
```

<CodeSnippet file="examples/docs/sandboxes/daytona.ts" title="server.ts" />

| Option | Description |
| --- | --- |
| `client` | A Daytona client. Defaults to `new Daytona()`, which reads `DAYTONA_API_KEY`. |
| `create` | Options for Daytona's `create`. |

The working directory is the sandbox's own working directory. A stopped sandbox is started again the next time the Actor uses it.

### Freestyle

```sh
npm add @rivet-dev/sandbox-adapter freestyle
```

<CodeSnippet file="examples/docs/sandboxes/freestyle.ts" title="server.ts" />

| Option | Description |
| --- | --- |
| `create` | Options for Freestyle's `vms.create`, or a function that receives the Actor context and returns them. Required, because `firewall` is required. |
| `client` | A Freestyle client. Defaults to `new Freestyle()`, which reads `FREESTYLE_API_KEY`. |
| `cwd` | Working directory inside the VM. Created when the Actor connects. Defaults to `/workspace`. |

A Freestyle VM has no network access until a `firewall` rule allows it. Commands run as `root` through Python 3, so the image must include it. Every `freestyle/ubuntu*` snapshot does.

### Docker

For local development. The provider runs the `docker` CLI on your worker, so it uses the current Docker context.

```sh
npm add @rivet-dev/sandbox-adapter
```

<CodeSnippet file="examples/docs/sandboxes/docker.ts" title="server.ts" />

| Option | Description |
| --- | --- |
| `image` | Image to run. It must include `/bin/sh`. Defaults to `ubuntu:24.04`. |
| `cwd` | Working directory inside the container. Created when the Actor connects. Defaults to `/workspace`. |
| `env` | Environment variables of the container. |
| `network` | Docker network to join. Set `"none"` for no network access. Defaults to `bridge`. The `host` network is rejected. |
| `ports` | Container ports to publish on a random `127.0.0.1` port. Read the address with `dockerPortAddress(sandboxId, port)`. |
| `keepImageEntrypoint` | Runs the image's own entrypoint, for images such as `cloudflare/sandbox` that start a server. By default the container runs an idle process. |
| `docker` | Path of the Docker CLI. Defaults to `docker`. |

Each sandbox is one container with the label `dev.rivet.sandbox-adapter.sandbox-id`. The container has no host mounts, no host environment, no privileged mode, and no host network. A kill or timeout ends the command and its child processes. A process that detaches from it, such as one started with `(command &)`, keeps running until the container stops.

## How the sandbox is managed

- The sandbox is created the first time the agent needs it.
- After a wake, the Actor reconnects to the same sandbox the first time a tool needs it. If it no longer exists, a new one is created and the old files are lost.
- Actions that don't touch the sandbox keep working while the provider is down.
- An existing Actor cannot switch to a different provider.
- Commands run with the sandbox's environment, not your worker's. File tools reject paths outside the working directory, but shell commands can reach anything inside the sandbox.
- Binary file writes aren't supported yet.

## Write your own provider

Any sandbox can back an agent. Implement <a href="https://github.com/rivet-dev/agents/blob/main/packages/sandbox-adapter/src/index.ts" target="_blank" rel="noopener noreferrer">`SandboxProvider`</a> and pass it as `sandbox`. One provider object is shared by every Actor of a definition, so keep no per-Actor state in it. The Actor stores the sandbox id.

| Member | Description |
| --- | --- |
| `name` | Stored next to the sandbox id, so a changed provider is detected on wake. |
| `create(c)` | Provisions a new sandbox and returns its id. |
| `connect(c, id)` | Connects to an existing sandbox and returns a `Sandbox`. Returns `undefined` when the sandbox no longer exists. |
| `suspend(c, id)` | Optional. Releases resources while the Actor sleeps. When omitted, the sandbox stops itself when idle or keeps running, depending on the provider. |
| `destroy(c, id)` | Optional. Deletes the sandbox when the Actor is destroyed. When omitted, the sandbox is left in place. |

The context `c` carries the owning Actor's `actorId` and a `client()` for your registry. The `Sandbox` that `connect` returns has a `cwd` and the operations the tools run: `exec`, `readFile`, `writeFile`, `mkdir`, `stat`, `readdir`, and `exists`. All paths are absolute paths inside the sandbox. See the <a href="https://github.com/rivet-dev/agents/blob/main/packages/sandbox-adapter/src/e2b.ts" target="_blank" rel="noopener noreferrer">E2B provider</a> for a complete example.
