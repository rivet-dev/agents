### What we'll build

- An `/mcp` route that speaks the Streamable HTTP transport and maps each MCP session id to one Actor.
- An `mcpSession` Actor per session that keeps the session's state, such as the signed-in user and open resources.
- MCP tools that call your API and stream progress back to the client.
- A setup that adds the server to Claude, ChatGPT, and Cursor as a remote MCP server.

### Similar tools

This is the same job as Cloudflare remote MCP servers with `McpAgent`, the Vercel MCP adapter, or hosting on Smithery. On Rivet each MCP session is an Actor, so its state stays in one place across requests and reconnects, and the Actor sleeps between calls.

### Open questions

- Rivet has no built-in MCP adapter that maps the Streamable HTTP transport and session ids to Actors. The guide would write this mapping by hand or wait for an adapter.
- Rivet has no OAuth provider for MCP authorization. Confirm which provider the guide uses, or leave auth out of the first version.
