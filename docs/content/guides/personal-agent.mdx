What we'll build:

- A sign-in where users enter their phone number, then the code they get by text.
- A `user` Actor per phone number that stores the sign-in in its SQLite database.
- An `assistant` agent per user that answers texts and can look up the weather.
- A Twilio webhook that routes each text to the sender's agent.

<Steps>

<Step title="Install">

```sh
npm add @rivet-dev/pi @earendil-works/pi-durable @earendil-works/pi-ai rivetkit hono @hono/node-server
```

</Step>

<Step title="Set up Twilio">

In the <a href="https://console.twilio.com" target="_blank" rel="noopener noreferrer">Twilio Console</a>, buy a phone number that can send SMS and create a <a href="https://www.twilio.com/docs/verify/api" target="_blank" rel="noopener noreferrer">Verify service</a> for the sign-in codes. Then set:

```sh
TWILIO_ACCOUNT_SID=AC...
TWILIO_AUTH_TOKEN=...
TWILIO_PHONE_NUMBER=+15550100000
TWILIO_VERIFY_SERVICE_SID=VA...
TWILIO_WEBHOOK_URL=https://<your-worker>/sms/webhook
ANTHROPIC_API_KEY=sk-ant-...
```

</Step>

<Step title="Create the agent">

Each user gets their own `assistant` agent, keyed by their phone number:

<CodeSnippet file="examples/docs/personal-agent/assistant.ts" title="assistant.ts" highlight="answer" />

- There's no step that creates an agent. The HTTP server calls `assistant.getOrCreate([phone])`, so a user's first text creates their agent and every later text reaches the same one, with the whole conversation so far.
- `onAnswer` runs for every answer the agent gives, with the agent's own context, so `c.key` is the user's phone number. It texts the answer back. It runs inside the agent's run, so an answer that finishes after a crash or restart still gets sent.

</Step>

<Step title="Create the user Actor">

Each phone number also gets a `user` Actor, keyed by the same number. It runs the two-step sign-in and remembers it in its SQLite database:

<CodeSnippet file="examples/docs/personal-agent/user.ts" title="user.ts" highlight="sign-in" />

- `sendCode` texts the user a code with Twilio Verify, which creates, expires, and rate limits it, so the Actor never stores it.
- `verify` checks the code and saves the sign-in in the `profile` table.
- `isSignedIn` tells the HTTP server whether a number has signed in.
- Keys use the E.164 format, such as `+15551234567`, because that's how Twilio sends the sender's number.

<Warning>
This sign-in is simplified. Any client can call `user` by phone number. In production, return a session after `verify`, such as a [JWT](/docs/jwt), and protect the Actor with [authentication](/docs/authentication).
</Warning>

</Step>

<Step title="Route requests">

The HTTP server has one route. Twilio sends every text to `/sms/webhook`, which checks the sender's `user` Actor and hands the text to their `assistant`:

<CodeSnippet file="examples/docs/personal-agent/server.ts" title="server.ts" highlight="webhook" />

- The webhook checks Twilio's signature, which covers the URL Twilio called. Set `TWILIO_WEBHOOK_URL` to exactly the URL you give Twilio, because a proxy or tunnel can change the URL the server sees.
- It answers with TwiML. An empty `<Response>` sends nothing, because the assistant replies on its own. A number that hasn't signed in gets a message telling it to sign in.
- `submit` hands the text to the agent and returns without waiting for the answer, so the webhook responds within Twilio's 15-second limit. The agent texts its answer from `onAnswer`.
- If a text is delivered twice, the `requestId` stops the agent from answering it again.

</Step>

<Step title="Try it">

In the Twilio Console, open your phone number. Under **Messaging**, set **A message comes in** to **Webhook**, `https://<your-worker>/sms/webhook`, `HTTP POST`. This is the same URL as `TWILIO_WEBHOOK_URL`.

<Note>
If you haven't deployed yet, test locally with <a href="https://ngrok.com/docs/getting-started/" target="_blank" rel="noopener noreferrer">ngrok</a>. Run the server with `npx tsx server.ts`, run `ngrok http 3000` in another terminal, and use the ngrok URL in place of `https://<your-worker>` for both the webhook and `TWILIO_WEBHOOK_URL`.
</Note>
