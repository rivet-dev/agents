### What we'll build

- An `/mcp` route that speaks Streamable HTTP and maps each signed-in user session to one `gatewaySession` Actor.
- A sign-in check that validates the user's token with your identity provider and loads their groups.
- A tool policy that merges `tools/list` from every upstream server and hides the tools the user's groups may not call.
- A router that sends each `tools/call` to the upstream server that owns the tool and streams the result back.
- An audit table in the Actor's SQLite database with the user, tool, arguments, and outcome of every call.

### Similar tools

This is the same job as the Docker MCP Gateway, Cloudflare MCP server portals, the Lasso MCP Gateway, or Kong AI Gateway's MCP support. On Rivet each user session is an Actor that holds the user's identity, allowed tools, and upstream connections in one place, so a reconnect does not repeat the sign-in or the tool discovery.

### Open questions

- Rivet has no MCP adapter that maps Streamable HTTP sessions to Actors, and no MCP client for the upstream side. Both would be written by hand with the MCP TypeScript SDK.
- Rivet has no per-user OAuth flow for MCP. Confirm which identity provider the guide uses and whether upstream servers get the user's token or a service token.
- Whether the audit log should stay in each session's SQLite database or be copied to a central store for search across users.
