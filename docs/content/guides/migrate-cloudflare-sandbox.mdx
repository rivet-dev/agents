In Cloudflare, `getSandbox()` returns a Durable Object that owns one container. In Rivet, a Rivet Actor owns one sandbox through [`@rivet-dev/sandbox-adapter`](/agents/docs/sandbox-adapter). The Actor's [key](/actors/docs/keys) gives the sandbox a stable identity, its actions replace the SDK methods, and the sandbox runs on a provider of your choice. Provider credentials and app secrets stay on your worker and never enter the sandbox.

## How concepts map

| Cloudflare Sandbox | Rivet | Notes |
| --- | --- | --- |
| `getSandbox(env.Sandbox, id)` | `client.sandbox.getOrCreate([id])` | The same [key](/actors/docs/keys) always reaches the same Actor and sandbox. |
| Sandbox Durable Object | A Rivet Actor that stores the sandbox id in [SQLite](/actors/docs/sqlite) | You write the actions, so you choose what callers can do. |
| Container image and `Dockerfile` | The provider's image or template | E2B templates, Daytona images, Freestyle snapshots, a Docker `image`, or agentOS `software`. |
| `exec()` | `sandbox.exec(command, { cwd })` | Returns `exitCode`, `stdout`, and `stderr`. |
| `execStream()`, `streamProcessLogs()` | `exec` with `onData`, sent as [events](/actors/docs/events) | Clients receive output while the command runs. |
| `startProcess()`, `killProcess()`, `listProcesses()` | `exec` that is not awaited, with an `AbortSignal` | `c.keepAwake` holds the Actor awake while the process runs. |
| `writeFile()`, `readFile()`, `mkdir()`, `exists()` | Methods of the same name on `Sandbox` | `readdir` lists a directory. Writes take a string. |
| `deleteFile()`, `renameFile()`, `moveFile()` | `rm` and `mv` through `exec` | |
| `gitCheckout()` | `git clone` through `exec` | The image must include `git`. |
| `createCodeContext()`, `runCode()` | Write a file and run it with `exec` | Each run is a new process. |
| `createSession()`, `setEnvVars()` | The `cwd` and `env` options of `exec` | Variables reach only the one command. |
| `exposePort()`, preview URLs | The provider's port URL | E2B `getHost`, Daytona `getPreviewLink`, Docker `dockerPortAddress`. |
| `sleepAfter` | `options.sleepTimeout` and `provider.suspend` in `onSleep` | See [Lifecycle](/actors/docs/lifecycle). |
| `keepAlive`, `setKeepAlive()` | `c.keepAwake(promise)` | Keeps the Actor awake while that work runs. |
| `destroy()` | `c.destroy()` and `provider.destroy` in `onDestroy` | Deletes the Actor and its sandbox. |

## Choose a provider

Every provider returns the same `SandboxProvider`, so the rest of your code does not change when you switch. This guide uses E2B. See [Providers](/agents/docs/sandboxes#providers) for the options of each one.

```sh
npm add rivetkit @rivet-dev/sandbox-adapter e2b
```

## Run commands

`exec` runs one command and waits for it to end. A non-zero exit code is a normal result, not an error. Passing `c.abortSignal` stops the command if the Actor shuts down. Raise `actionTimeout` in the Actor's options for commands that run longer than 60 seconds.

## Run background processes

The adapter has no separate process API, so `startProcess` becomes an `exec` that the action does not wait for. An `AbortController` per process replaces `killProcess`, and `c.keepAwake` holds the Actor awake until the process ends.

<CodeSnippet file="examples/docs/migrate-cloudflare-sandbox/server.ts" title="server.ts" region="process" />

The list of running processes lives in memory. If the Actor restarts, its processes are stopped with it, so start them again from your app or from `onWake`.

## Expose a port

Each provider gives a sandbox port its own URL: E2B's `getHost`, Daytona's `getPreviewLink`, or Docker's `dockerPortAddress` for local development. The adapter does not wrap them, so call the provider's SDK with the stored sandbox id.

Unlike a Cloudflare preview URL, there is no `proxyToSandbox` step in your Worker. Check your provider's access controls before you expose a port, since its URL may be public.

## Sleep and destroy

Cloudflare stops an idle container after `sleepAfter`. A Rivet Actor sleeps after `options.sleepTimeout`, and `onSleep` suspends the sandbox through the provider. Destroying the Actor deletes the sandbox in `onDestroy`.

What happens to the sandbox while the Actor sleeps depends on the provider:

| Provider | While the Actor sleeps | When the Actor is destroyed |
| --- | --- | --- |
| E2B | Paused | Deleted |
| Daytona | Stopped | Deleted |
| Freestyle | Paused | Deleted |
| agentOS | Sleeps when idle, and keeps its files | Left in place |
| Docker | Stopped | Removed |

## Differences to plan for

- **Files survive sleep.** A Cloudflare sandbox loses its files when its container sleeps. Every provider above keeps them while the Actor sleeps. If a provider no longer has the sandbox, `openSandbox` creates a new, empty one.
- **No shell sessions.** Each `exec` starts a new shell, so `cd` and `export` do not carry over. Pass `cwd` and `env` on every command instead of `createSession`.
- **Writes are text only.** `writeFile` takes a string. For binary files, write base64 and decode it with `exec`.
- **No port readiness helper.** There is no `waitForPort`. Poll the port with `exec`, for example with `curl`, until it answers.
- **Provider features stay in the provider's SDK.** Terminals, snapshots, and file watching have no adapter API. Call the provider directly with the stored sandbox id, as the preview URL example does. E2B, for example, has `pty`, `createSnapshot`, and `files.watchDir`.
- **No bucket mounts.** There is no `mountBucket`. Download objects with `exec`, or read them from your Actor and write them into the sandbox.
- **Resources come from the provider.** Instance types, CPU, memory, and disk are set in the provider's create options, not in Rivet.
- **Your worker hosts the Actor.** The Actor runs wherever you run RivetKit, on [Rivet Cloud](https://dashboard.rivet.dev) or your own infrastructure. It does not need to run on Cloudflare.
