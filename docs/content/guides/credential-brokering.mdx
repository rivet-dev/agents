### What we'll build

- A `connections` Actor per user that stores that user's GitHub and Stripe tokens after they connect each account.
- Host functions such as `agentos-github` and `agentos-stripe` that the code in the VM calls like any CLI command or JavaScript function.
- A broker on the agent's Actor that looks up the current user's token, attaches it, and makes the API call.
- A check that the VM's environment and filesystem never contain a key, even when the model asks for one.

### Similar tools

This is the same job as Vercel Connect, Arcade.dev, Composio, or 1Password agent credentials. On Rivet the broker is a host function on the same Actor as the agent, so the token lookup is scoped to that Actor's user and the key never crosses into the VM.

### Open questions

- Host functions are only available with the embedded agentOS library, not on hosted VMs. The Rivet Agents agentOS sandbox runs a hosted VM, so the guide needs the embedded library inside the agent's Actor, or it would broker credentials through custom tools instead.
