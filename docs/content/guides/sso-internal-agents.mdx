### What we'll build

- An OIDC sign-in with Okta or Microsoft Entra ID in front of your internal agent.
- A callback route that reads the user's identity and groups and issues a short-lived scoped Rivet JWT.
- An `employeeAgent` per employee that the JWT can reach, and nothing else.
- Tools that call internal APIs with the signed-in employee's identity, so each system applies its own access rules.

### Similar tools

This is the same job as Glean, Microsoft Copilot Studio, or Vercel Connect. On Rivet each employee gets their own agent, and the JWT your backend issues decides which agent a browser can reach, so the SSO session maps straight to one Actor.

### Open questions

- Rivet has no built-in SSO gate. The guide does the OIDC sign-in in your backend and only uses Rivet for the scoped JWT.
