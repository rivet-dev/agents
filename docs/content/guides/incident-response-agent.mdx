### What we'll build

- A webhook route that verifies PagerDuty or Datadog alerts and starts one `incidentAgent` per incident, keyed by the incident id.
- Read-only tools that pull recent logs, metrics, and deploys for the affected service.
- An agentOS VM per incident where the agent runs runbook scripts with bash, Node, or Python, with network access limited to your internal endpoints.
- Findings posted to the incident's Slack channel, with an approve button that the agent waits on before it runs any fix.
- A timeline in the agent's state that becomes the draft postmortem when the incident resolves.

### Similar tools

This is the same job as PagerDuty AIOps, Rootly AI, incident.io AI SRE, Cleric, or Resolve.ai. On Rivet each incident is a durable agent that keeps its own timeline and VM, so it can wait an hour for a human to approve and then continue with everything it found.

### Open questions

- Rivet Agents has no PagerDuty or Datadog connector. The webhook verification and the incident lookups would be custom routes and tools.
- Rivet Agents has no built-in approval flow. The guide would follow the [Human in the Loop](/agents/docs/human-in-the-loop) pattern with Slack buttons, which needs a Slack interactivity route the Slack connector may not cover.
