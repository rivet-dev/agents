### What we'll build

- A `chatAgent` per conversation, keyed by the conversation id, that keeps its history and plan in its own SQLite database.
- A backend route that hands each message to the agent with `submit` and returns without waiting for the answer.
- A chat client that streams the agent's events and picks the answer back up after a reload.
- Tools that call your API and are not run twice after a crash.
- A test that kills the worker mid-run and shows the agent finishing the same run after a restart.

### Similar tools

This is the same job as Temporal AI agents, Inngest AgentKit, Vercel Workflow DevKit agents, or the Cloudflare Agents SDK. On Rivet the agent is itself the durable unit: each step is saved to the agent's own SQLite database, so there is no separate workflow engine, queue, or database to run next to it.
