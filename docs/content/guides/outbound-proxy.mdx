### What we'll build

- A corporate proxy such as Zscaler or Squid as the only route from your Rivet nodes to the internet.
- An allowlist on the proxy that names the model APIs, package registries, and partner APIs your agents may reach.
- Agents, plain Actors, and agentOS VMs that all send their outbound traffic through that proxy.
- A test that shows a request to a host outside the allowlist fails at the proxy.

### Similar tools

This is the same job as Zscaler for AI, Netskope, or Cloudflare Gateway. On Rivet the agent, its tools, and its sandbox all run on your nodes, so one proxy setting on those nodes would cover every request the agent makes.

### Open questions

- Rivet has no egress proxy setting for Actors or agentOS VMs today. The guide depends on one, or on routing at the network level, and agentOS VMs need a way to send guest traffic through the proxy.
