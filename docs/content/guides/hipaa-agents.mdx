### What we'll build

- A self-hosted Rivet deployment in your own AWS or Azure account, so PHI stays on infrastructure you control.
- A `patient` Actor per patient that keeps that patient's PHI in its own SQLite database.
- A `patientAgent` per patient that answers clinician questions and can only read its own patient's chart.
- An `auditLog` Actor that records who read which record and when.
- Model calls sent only to Azure OpenAI or Amazon Bedrock under a signed BAA.

### Similar tools

This is the same job as building on AWS HealthLake, Azure Health Bot, or Hathr. On Rivet each patient's data and agent live in Actors keyed by patient, so one patient's records are never loaded next to another's, and the whole stack runs in your account.

### Open questions

- Rivet Cloud has no published BAA. The guide targets a self-hosted Rivet deployment and does not cover Rivet Cloud.
