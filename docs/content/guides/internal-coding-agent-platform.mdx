### What we'll build

- Three ways to start a task: a Slack mention, a label on a GitHub issue through the connectors, and a form in a web UI.
- A `codingSession` agent per task that keeps the plan, the branch, the transcript, and the sandbox id.
- A sandbox from `@rivet-dev/sandbox-adapter` with the repository cloned, where the agent edits code and runs the tests.
- Progress messages in the Slack thread or issue, and a pull request opened when the tests pass.
- A `sessionIndex` Actor and a dashboard page that lists running and finished sessions with links to each transcript.

### Similar tools

This is the same job as Ramp's Inspect, the GitHub Copilot coding agent, Cursor background agents, or OpenAI Codex cloud. On Rivet you run it on your own infrastructure: each task is a durable agent that can work for hours, survive restarts, and wait for review without holding a sandbox or a request open.

### Open questions

- How git authenticates to private repositories inside the sandbox. The token could be passed in the clone URL or an environment variable on E2B, Daytona, or Freestyle. On agentOS, keeping the token out of the VM with host functions is unverified.
- Whether the coding agent is Rivet Agents with `CodingTools` or a coding agent CLI such as Claude Code run through Sandbox Agent. The diagram assumes the first.
