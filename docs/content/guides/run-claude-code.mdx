### What we'll build

- A `claudeSession` Rivet Actor per session, keyed by session id, that stores the transcript and the sandbox id.
- A sandbox for each session from the sandbox adapter, with Claude Code installed when the sandbox is created.
- A prompt action that runs `claude -p` with `exec` and streams stdout to the client as it arrives.
- Follow-up prompts that reconnect to the same sandbox, so the files and the Claude Code session are still there.

### Similar tools

This is the same job as Anthropic's Claude Code GitHub Actions, hosting the Claude Agent SDK yourself, or the E2B Claude Code template. On Rivet, the Actor is the session: it holds the transcript and the sandbox id, so a client can drop off and reconnect, and the sandbox can be swapped to another provider without changing the Actor.

### Open questions

- Which providers can run the Claude Code CLI. E2B and Daytona can run it in a full Linux image; whether agentOS runs it is not confirmed.
- How `ANTHROPIC_API_KEY` reaches the sandbox, for example as an `exec` environment variable, without being written to the sandbox's disk.
