### What we'll build

- A `userMemory` Actor per user that stores facts in its SQLite database and searches them with full-text search.
- `remember` and `recall` tools that every conversation's agent shares, so a fact learned in one chat is available in the next.
- An optional `summarize` workflow that reads a finished conversation and saves the facts it finds.
- An optional hook for an embedding API or vector store when keyword search is not enough.

### Similar tools

This is the same job as Mem0, Zep, Letta, the LangGraph memory store, or Cloudflare Agents memory. On Rivet the memory is one Actor per user with its own database, so there is no shared memory service to run, and each user's facts stay apart from everyone else's.

### Open questions

- Actor SQLite has no vector search yet, such as sqlite-vec. Semantic recall needs an external vector store or embedding API for now.
- FTS5 full-text search in Actor SQLite is unverified. Confirm it is compiled in before the guide depends on it.
