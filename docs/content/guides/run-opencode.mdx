This page is not written yet. The outline below is what it will cover.

### What we'll build

- An `opencodeSession` Rivet Actor per session, keyed by session id, that stores the transcript and the sandbox id.
- A sandbox for each session from the sandbox adapter, with OpenCode installed when the sandbox is created.
- A prompt action that runs `opencode run` with `exec` and streams its output to the client.
- A variant that starts `opencode serve` once per sandbox and sends each prompt to that server instead of starting a new process.

### Similar tools

This is the same job as the opencode GitHub agent or the OpenCode templates from Daytona and E2B. On Rivet, the session lives in an Actor that keeps the transcript and the sandbox id, so you choose the model and the sandbox provider separately and can change either one later.

### Open questions

- Which providers can run OpenCode. E2B and Daytona can run it in a full Linux image; whether agentOS runs it is not confirmed.
- How the model provider's API key reaches the sandbox, for example as an `exec` environment variable, without being written to the sandbox's disk.
- Whether `opencode serve` needs a port exposed from the sandbox, and which providers allow that.
