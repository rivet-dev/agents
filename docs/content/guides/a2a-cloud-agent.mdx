This page is not written yet. The outline below is what it will cover.

### What we'll build

- An agent card at `/.well-known/agent-card.json` that lists the agent's skills and where to call it.
- An `/a2a` JSON-RPC route that handles `message/send`, `message/stream`, `tasks/get`, and `tasks/cancel`.
- An `a2aAgent` per A2A task that keeps the task's history and state, so a client can reconnect and read it later.
- A test that calls the agent from an agent built with Google ADK.

### Similar tools

This is the same job as A2A servers in Google ADK, LangGraph, the Microsoft Agent Framework, or AWS Bedrock AgentCore. On Rivet each A2A task is its own agent, so a long task keeps running after the caller disconnects, and its state is there when the caller comes back.

### Open questions

- Rivet has agent-to-agent messages between its own agents, but no A2A protocol endpoint. The agent card, task methods, streaming, and push notifications would be written by hand for now.
- A2A push notifications to a caller's webhook are not covered by this design. Confirm whether the first version needs them.
