### What we'll build

- An `agentRegistry` Actor that stores each team's agent definitions: the system prompt, the tools and connectors it may use, and a monthly usage limit.
- A `teamAgent` per team, agent, and user, so each employee gets a private conversation history with the same agent definition.
- A `/chat` route behind SSO that resolves the employee's team and routes the message to the right agent.
- A shared tool catalog and the Slack, GitHub, and Linear connectors that admins can switch on per agent.
- A usage counter in each agent that stops new runs when the team reaches its limit.

### Similar tools

This is the same job as OpenAI AgentKit, Microsoft Copilot Studio, Glean Agents, or Dust. On Rivet the platform is your own code: each agent instance is a durable agent with its own history and state, and you choose the models, the tools, and where the data is kept.

### Open questions

- Rivet has no SSO gate. The guide would check the SSO session in the server route and pass the user and team to the Actor, or wait for a built-in auth integration.
- Defining agents at runtime with custom tool code needs Dynamic Apps, which is in preview. The first version would limit admins to prompts and tools from a fixed catalog.
