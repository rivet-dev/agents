### What we'll build

- An `agentData` Actor per agent, keyed like the agent, with memory, task, and result tables in its SQLite database.
- Tools that save and recall memories through actions on that Actor.
- Task and result tables that let a long job pick up where it stopped after a restart.
- An action that lets your app read an agent's results without going through the model.

### Similar tools

This is the same job as Turso with a database per agent, Neon for agents, or Cloudflare Agents SQL storage. On Rivet the database lives inside an Actor that shares the agent's key, so it is created on first use and there is nothing to provision when a new agent starts.

### Open questions

- A `pi()` agent takes no `db` option, so its tools cannot use `c.db` in the agent's own Actor. This design keeps the data in a second Actor per agent. Putting it in the agent's Actor needs a `db` option on `pi()`.
