### What we'll build

- A backend route that signs the user in and mints a JWT with `issueToken` whose grants cover only that user's Actors.
- An `assistant` agent per user whose tools create their Rivet client with that JWT instead of your server credentials.
- An `orders` Actor per user that the tools can reach, and a `billing` Actor that they cannot.
- A test that asks the agent to touch another user's data and shows the call is rejected.

### Similar tools

This is the same job as Auth0 for AI Agents, WorkOS FGA, or Permit.io. On Rivet the limit is the token itself: Rivet checks the grants before routing each call, so a prompt injection cannot widen what the agent's tools can reach.

### Open questions

- Rivet Agents has no documented way to hand a per-user JWT to an agent's tools. The guide assumes the backend passes it with each prompt. Tokens cannot be revoked, so a run keeps its token until it expires.
