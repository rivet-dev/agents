### What we'll build

- A `codingSession` Rivet Actor per session that owns one sandbox through the sandbox adapter and stores its id.
- A way to start any CLI coding agent in that sandbox with `exec`, and stream its output to whoever is watching.
- A `sessionIndex` Actor that every session registers with, so the dashboard can list sessions and their status.
- Idle handling that suspends the sandbox when a session goes quiet and connects to it again on the next prompt.
- A dashboard that lists sessions, opens one, and shows its live output.

### Similar tools

This is the same job as Vercel Sandbox, E2B, Daytona, Modal, or Runloop. Those provide the sandbox; on Rivet, the session around it is an Actor that keeps the sandbox id and transcript, decides when to suspend, and can sit on top of any of those providers through the adapter.

### Open questions

- Which providers can run each CLI agent. agentOS may not run every agent CLI; E2B and Daytona can run them in a full Linux image.
- How each agent's API key reaches the sandbox without being written to its disk.
