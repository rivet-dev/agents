### What we'll build

- A `codexSession` Rivet Actor per session, keyed by session id, that stores the transcript and the sandbox id.
- A sandbox for each session from the sandbox adapter, with the Codex CLI installed when the sandbox is created.
- A prompt action that runs `codex exec` with `exec` and streams its output to the client line by line.
- Follow-up prompts that reconnect to the same sandbox and continue the previous Codex session.

### Similar tools

This is the same job as OpenAI Codex cloud or the Codex GitHub Action. On Rivet, each session is an Actor you address by key, so your app decides where the sandbox runs and keeps the transcript next to the session instead of in a hosted task list.

### Open questions

- Which providers can run the Codex CLI. E2B and Daytona can run it in a full Linux image; whether agentOS runs it is not confirmed.
- How the OpenAI API key reaches the sandbox, for example as an `exec` environment variable, without being written to the sandbox's disk.
