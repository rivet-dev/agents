### What we'll build

- A `codeRunner` Rivet Actor per tenant or per run that holds the limits and a history of runs in its SQLite database.
- A `run` action that writes the code into a sandbox from the sandbox adapter and executes it with `exec`.
- Timeouts and output limits on every run, so a run that hangs or floods output is killed.
- A result with stdout, stderr, and the exit code, returned to your app.
- A provider setting in config, so moving from agentOS to E2B, Daytona, or Freestyle does not change the Actor.

### Similar tools

This is the same job as E2B, Vercel Sandbox, the Cloudflare Sandbox SDK, Modal Sandboxes, or Daytona. On Rivet, a per-tenant Actor sits in front of the sandbox, so limits, history, and the sandbox id live with the tenant, and the provider underneath is a config choice.

### Open questions

- How CPU, memory, and network limits are set per provider. The adapter's `exec` has `timeoutMs`, but other limits come from each provider's create options and differ between them.
